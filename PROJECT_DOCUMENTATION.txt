PROJECT TITLE
Photo Album Management System


PROJECT DESCRIPTION
A production-ready Django 6.0.5 web application for managing photo albums with secure user authentication, cloud-based image storage via Cloudinary, and comprehensive role-based access control. The application is optimized for deployment on Render.com with PostgreSQL in production and SQLite for development. Users can create albums, upload photos to the cloud, manage profiles, and maintain complete control over their content through a permissions-based system.

SYSTEM FEATURES
User Authentication: Secure registration with email validation, login/logout functionality, password reset via email tokens, session-based authentication, user profiles with bio and avatar support, automatic UserProfile creation on registration.

Album Management: Create personal photo albums, edit album name and description, delete albums with confirmation dialogs, view all personal albums with pagination, automatic timestamps (created_at, updated_at), unique album names per user to prevent duplicates.

Photo Upload and Management: Upload photos directly to Cloudinary cloud storage with automatic image optimization, store photo metadata including title and description, edit photo details after upload, delete photos with confirmation, track photo count per album.

User Profiles: Customizable user profiles with biography and avatar URL support, display user statistics showing album and photo counts, profile editing capability for users to update information.

Role-Based Access Control: Only authenticated users can access the application, users can only view and manage their own content, ownership verification enforced on all CRUD operations via UserPassesTestMixin, superuser access to full admin panel via Django admin interface.

Email Integration: Password reset functionality with secure email tokens, automated email notifications for authentication events, configurable email backend for development and production environments.

Security Features: CSRF protection on all forms, XSS prevention through template auto-escaping, SQL injection prevention via Django ORM, secure password hashing with PBKDF2 + SHA256, minimum 8 character password requirement, HTTPS enforcement in production, secure cookie settings (HttpOnly, Secure, SameSite).

SETUP INSTRUCTIONS
Prerequisites: Python 3.11 or higher, Git version control, pip package manager, Cloudinary account (free tier at cloudinary.com), PostgreSQL client tools.

Step 1 - Clone Repository: git clone https://github.com/diangchristian/IT383-Assignment6 && cd cloud-render

Step 2 - Create Virtual Environment: Windows: python -m venv venv && venv\Scripts\activate | macOS/Linux: python3 -m venv venv && source venv/bin/activate

Step 3 - Install Dependencies: pip install -r requirements.txt

Step 4 - Environment Configuration: Create .env file in project root with SECRET_KEY (generate using get_random_secret_key()), DEBUG=True for local development, ALLOWED_HOSTS=localhost,127.0.0.1, DATABASE_URL=sqlite:///db.sqlite3 for development, CLOUDINARY_CLOUD_NAME, CLOUDINARY_API_KEY, CLOUDINARY_API_SECRET

Step 5 - Initialize Database: python manage.py migrate to run all database migrations, python manage.py createsuperuser to create admin account, enter username, email, and password when prompted

Step 6 - Start Development Server: python manage.py runserver, access application at http://localhost:8000, access admin panel at http://localhost:8000/admin with superuser credentials

Database Design: auth_user table stores Django built-in user data with hashed passwords. gallery_album table stores album information with owner foreign key and unique constraint on (owner_id, name). gallery_photo table stores photos with Cloudinary image field and relationships to albums and users. accounts_userprofile table extends user model with one-to-one relationship storing bio and avatar URL.

Project Structure: recipe_project/ contains Django settings and configurations. accounts/ app handles user registration, authentication, login, logout, password reset, and user profiles. gallery/ app manages album creation/editing/deletion and photo uploads to Cloudinary. templates/ directory contains all HTML templates organized by app. manage.py is the Django management script. requirements.txt lists all Python dependencies.

Admin Panel: Access at /admin/ to manage users, user profiles, albums, photos, permissions, and groups. Create superuser with createsuperuser command. Django admin automatically generated based on model definitions.


DEPLOYMENT INFORMATION
Platform: Render.com provides free tier hosting suitable for testing and production deployments.

Database Setup: Create PostgreSQL database by going to Render Dashboard (https://dashboard.render.com), clicking New + then PostgreSQL, naming the database photo-album-db with database name photo_album, selecting appropriate region and plan (Free for testing or Standard for production), and copying the Internal Database URL for environment configuration.

Web Service Creation: Create a new web service by clicking New + then Web Service, connecting your GitHub repository, selecting the main branch, and authorizing Render to access your repository.

Configuration: Set service name to photo-album-manager (or preferred name), environment to Python 3, build command to ./build.sh, start command to gunicorn recipe_project.wsgi:application --bind 0.0.0.0:$PORT, and plan appropriate to your needs. Select the same region as the database for optimal performance.

Environment Variables: Add SECRET_KEY generated with get_random_secret_key(), set DEBUG=False for production, set ALLOWED_HOSTS to your Render domain (e.g., photo-album-manager.onrender.com), set DATABASE_URL to the PostgreSQL Internal Database URL from Render, add CLOUDINARY_CLOUD_NAME, CLOUDINARY_API_KEY, CLOUDINARY_API_SECRET from your Cloudinary account.

Deployment Process: Commit all changes with git commit -m "message", push to GitHub with git push origin main, Render automatically detects the push and triggers deployment via build.sh script, monitor deployment progress in Render dashboard Logs tab, access application once deployment completes at the assigned Render URL.

Build Script: The build.sh script installs Python dependencies from requirements.txt, collects static files for production serving via WhiteNoise, and runs database migrations to initialize PostgreSQL schema.

Pre-Deployment Checklist: Verify DEBUG=False in production settings, generate secure SECRET_KEY and store in environment variables, ensure .env file is in .gitignore and never committed, collect all static files, run all database migrations, configure Cloudinary credentials, set ALLOWED_HOSTS to production domain, enable HTTPS redirect, test application locally before deployment.

Post-Deployment Verification: Check application health at https://your-app-url.onrender.com, verify admin access at /admin/, check application logs in Render dashboard for any errors, test user registration and login functionality, test photo upload to Cloudinary, verify email functionality if configured.

URL Patterns for Testing: /accounts/register/ for registration, /accounts/login/ for login, /accounts/logout/ for logout, /accounts/profile/ for user profile, /accounts/profile/edit/ for profile editing, /accounts/password_reset/ for password reset, /albums/ to list albums, /albums/create/ to create album, /albums/<id>/ to view album, /albums/<id>/edit/ to edit album, /albums/<id>/delete/ to delete album, /photos/<id>/ to view photo, /photos/<id>/edit/ to edit photo, /photos/<id>/delete/ to delete photo, /photos/create/<album_id>/ to upload photo.

Development Commands: python manage.py runserver to start development server, python manage.py test to run tests, python manage.py makemigrations to create migrations, python manage.py migrate to apply migrations, python manage.py showmigrations to view migration status, python manage.py shell for interactive shell, python manage.py collectstatic --noinput for collecting static files, python manage.py check to check configuration.

Email not sending - check EMAIL settings and SMTP configuration. Never enable DEBUG=True in production.
